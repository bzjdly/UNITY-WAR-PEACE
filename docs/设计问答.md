# WAR-PEACE 设计问答追踪

> 用途：按设计依赖顺序向制作人提问，记录回答状态，并把确认内容回填到根目录的 `大纲.md`。  
> 原则：每次只聚焦一组相互关联的问题；未回答或存在分歧的内容保持为“待确认”。

## 状态说明

| 状态 | 含义 |
| --- | --- |
| 待提问 | 尚未向制作人提出 |
| 等待回答 | 已提出，尚未收到答案 |
| 已回答 | 已收到明确答案 |
| 待补充 | 已有方向，但仍缺少可执行细节 |
| 已确认 | 已回填到 `大纲.md`，可作为后续设计依据 |
| 暂缓 | 当前阶段不需要决定，或依赖后续原型验证 |

### Q02：玩家身份、时间与战役结构

**状态：已确认**

**回答**

1. 玩家代表一位类似领主的角色，并拥有一块属于自己的土地。
2. 不存在具名的玩家化身，玩家以俯视或上帝视角直接控制臣民、士兵和军队。
3. 战役暂定为无限沙盒；此描述已由 Q09 修正为“沙盒结构，但击败强敌后通关”。
4. 大地图实时推进，可以暂停和加速，不采用回合制。
5. 当前一局失败或结束后，重新开始一局。
6. 玩家可以同时指挥多支部队并管理多处领地。

### Q09：世界压力与敌国行为

**状态：已确认**

**回答**

1. 敌国与玩家类似，会随局势发展和变化。
2. 敌国通过战斗骚扰玩家。
3. 暂不设计提前预警或专用情报提示。
4. 敌国的扩张和势力消长独立于玩家进行。
5. 玩家可以通过交易缓解敌国压力。
6. 击败当前强大敌国后直接通关，目前没有新的长期挑战。
7. 战斗失败的一方会丢失领土。

**重要修正**

此前“无限沙盒、没有预设结局”的描述更新为：沙盒结构持续运行，但当前一局以击败强大敌国、完成通关为终点。

### Q12：战斗触发与场景流程

**状态：已确认**

6. 战斗结束后，双方在战略层原位置返回。
7. 首版基础作战方式包含近战和远程。
8. 进攻城镇必须进入独立战斗。

## 已确认结论

### 世界与地图

- 抽象、无缝、可编辑的开放世界地图。
- 战略地图采用格子结构。
- 半架空中国王朝末期。
- 明代水平的成熟冷兵器与少量初级热武器。

### 数据规则

- 数量型内容统一由 Data 数据层或配置代码控制。
- 数量、生成和平衡参数需要便于开发调试，不写死在玩法逻辑中。

### 玩家与战役

- 玩家代表一个拥有土地的领主势力，不存在具名玩家化身。
- 战略层采用上帝视角，直接控制臣民、军队和领地。
- 战役采用沙盒结构，以击败强敌通关为终点。
- 大地图时间为实时制，支持暂停和加速。
- 支持同时指挥多支部队并管理多处领地。
- 当前一局结束后重新开始。

### 战略层

- 玩家直接控制士兵和领土内建筑规划。
- 暂停时保留完整操作能力。
- 大地图存在战争迷雾和情报限制。
- 进入战斗后，战略层其他内容暂停。
- 大地图速度档位属于 Data 数值。

### 城镇与经济

- 领地长期目标是生产兵员，并通过发展提供成就感。
- 经济资源包括货币、石材、木材和食物。
- 建筑采用网格规划。
- 建筑支持升级、拆除、损毁、停用和岗位分配。
- 人口承担后勤与兵员生产职责。
- 领地归属可通过战争或外交改变。
- 势力与外交采用类似《文明》的整体方向，具体边界待补充。

### 开发顺序

- 当前优先完成即时战斗原型。
- 运营、外交和文明式势力系统暂缓，不视为取消。
- 战斗完成后再回到领主经营和势力系统。

### 即时战斗

- 玩家以编队级别控制部队。
- 操作模式直接参考《绝境北方》。
- 战斗实时进行，并允许暂停。
- 部队表现由自身战斗力和城镇幸福度决定。
- 冷兵器与初级热武器的差异主要通过数值体现。
- 部队可以主动撤退，城镇负责伤亡支持，战果运回大本营。
- 部队通过经验提升战斗力。
- 战斗胜利可以获取敌方城镇。
- 首版战斗场景暂缓，先使用手动搭建的测试战场。
- 当前战斗设计已经足够进入原型阶段，剩余细节在制作中继续明确。

### 战役成长与失败

- 开局拥有至少一块领地和部分士兵，具体数量由 Data 决定。
- 丢失全部领土即失败并重开，目前没有翻盘机制。
- 部队在领地内部获取经验并升级。
- 当前没有扩张领土、生产军队和部队升级以外的势力成长路线。
- 强大敌国会像玩家一样独立发展，并通过战斗骚扰玩家。
- 首版暂不设计任务与剧情事件。

### 世界压力与通关

- 敌国拥有独立发展和变化。
- 敌国主要通过战斗施压，暂不提供提前预警。
- 玩家可以通过交易缓解敌国压力。
- 战斗失败的一方会丢失领土。
- 击败当前强大敌国即通关，目前没有后续无尽挑战。
- 沙盒结构持续运行，但当前一局具有明确终点。

### 战斗流程

- 移动遭遇触发战斗。
- 战术战斗和自动结算并存。
- 战略部队直接转换为战场编队。
- 战场地形可以关联战略地图位置。
- 战前可以避免交战或撤退。
- 战斗结束后返回战略层原位置。
- 首版基础作战方式为近战和远程。
- 进攻城镇必须进入独立战斗。

### 视觉与技术基线

- 战略层和战斗层统一采用 2.5D、斜 45 度视角。
- 美术采用极简、低面数风格。
- 首版使用替代素材和占位界面。
- 音效与正式美术资源暂缓。
- 首版优先支持 Windows，性能按正常标准开发。

### 游戏模式与外部功能

- 纯单机。
- 自动存档与手动存档并存。
- 键鼠操作。
- 首版不做多人、Mod 和玩家自制地图。
- 发行平台和分发方式暂不考虑。

### 第一阶段范围

- 只完成独立战斗原型，不接入战略层。
- 必须包含玩家编队操控、敌人 AI 和战场地形生成。
- 必须包含近战、远程、基础胜负和伤亡结算。
- 所有数值、场景参数和敌人类型通过 Data 调试。
- 前提是不影响验证核心表现，可以继续使用替代素材。
- 经营、外交、遭遇切换、自动结算、撤退和返回流程均不在第一阶段。
- 进入经营系统的时机暂缓确定。
